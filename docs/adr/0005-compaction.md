# ADR 0005: full compaction и безопасная очистка

Статус: принято для неопубликованного прототипа по запросу пользователя. WAL, SST и manifest остаются v1.

## Варианты

1. Загрузить всю базу в map и переписать: просто, но требует памяти под все values.
2. Ручное полное слияние всех активных SST и memtable через существующий heap merge: выбрано. Значения передаются по одному в streaming SST writer.
3. Leveled/tiered фоновая compaction: лучше ограничивает write amplification, но требует политики уровней, частичного покрытия tombstones и управления конкуренцией. Отложено.

## Протокол

Compaction охватывает все активные источники. Свежая версия побеждает, tombstones подавляют старые значения и не записываются в результат. Ограничение выдачи scan=100 к compaction не применяется. Создаются один SST с живыми ключами и новый пустой WAL. Пустой результат публикуется без SST.

Порядок: create_new SST → запись, flush, sync → проверка SST → новый WAL с synced header → sync_directory имён → manifest.tmp write/flush/sync → atomic rename → sync_directory → переключение handles. Старые handles закрываются до удаления файлов. Любая ошибка до завершения публикации блокирует mutations до reopen; ничего старого не удаляется. Reopen использует единственный видимый manifest, без fallback.

После публикации удаляются только строго распознанные generation-файлы, не перечисленные в активном manifest: SST, WAL и manifest.tmp. LOCK, MANIFEST и неизвестные имена сохраняются. Перед любой очисткой выполняется дополнительный sync_directory: это фиксирует видимый manifest и при reopen после неизвестного исхода предыдущего rename/sync. После удаления выполняется sync_directory.

CleanupReport содержит число удалённых файлов и явные ошибки с именем/операцией/source. Ошибка очистки не отменяет уже опубликованное состояние и не блокирует безопасные mutations. CompactionReport отдельно сообщает tables_before/after и cleanup. collect_garbage позволяет повторить очистку без переписывания данных. Poisoned database не выполняет GC. Ошибка barrier/list прекращает очистку до первого удаления; ошибки отдельных удалений собираются. NotFound при удалении уже отсутствующего orphan допустим.

Если SST не больше одного, tombstones нет и memtable пуста, compact только очищает мусор. Нет автоматической очистки при open/flush, фоновых потоков или неявного исправления повреждений.

## Ограничения

На выходе пока максимум один SST: 1M entries и 64 MiB index. Превышение выдаёт ошибку без смены manifest, частичный файл остаётся orphan. Память: существующие индексы/memtable, один heap key на источник, индекс нового SST и ограниченный key/value frame; все values базы не собираются. На время слияния нужно дополнительное место под новую живую версию и WAL; старые файлы существуют до durable publication. Переписываются все живые значения; это измеримый первый шаг, не оптимальная стратегия больших баз.

Linux fault/process tests не доказывают power-loss safety на всех ФС/ОС. Удаление через Directory требует явной реализации remove_file; default Unsupported сохраняет совместимость других адаптеров и отражается в cleanup.errors.

## Проверки

Сравнение с map, более 100 ключей, бинарные/пустые ключи, tombstones и повторная запись, unflushed delta, reopen, пустая база, повторный compact, освобождение места, сохранение неизвестных файлов. Отказы до публикации сохраняют подтверждённое состояние; ошибки очистки видимы и допускают повтор. Проверка реальных CLI compact/gc и process kill вокруг публикации/очистки.

# ADR 0001: сторы поверх KV и React entry point

Статус: принято для неопубликованного v0.1, 27 октября 2026.

## Задача

Добавить runtime-валидируемые сторы, миграции и React с селекторами, сохранив независимость KV от React и будущего движка DB.

## Варианты

1. Расширить KV схемами и хуками: меньше сущностей, но смешиваются хранение, модель данных и UI.
2. Отдельный слой Store поверх KV, React как отдельный entry point: больше явных контрактов, зато тестируется без React и работает на разных KV backend.
3. Сразу универсальный async Store для будущего DB: потенциально единый API, но вводит асинхронность и lifecycle до существования движка.

Выбрано 2. Async DB API проектируется на собственном этапе; не маскируем localStorage под транзакционную базу.

## Контракт

`defineStore({ key, version, defaults, validate, migrations? })` возвращает StoreDefinition<T>.
`createStore(kv: KV<unknown>, definition)` возвращает Store<T>:

- getSnapshot(): T;
- getServerSnapshot(): T;
- set(value: T): void;
- update(updater: (previous: T) => T): void;
- reset(): void;
- subscribe(listener: () => void): () => void.

Положительные целочисленные версии. Envelope: `{ __stowtree: 1, version, value }`.
`migrations[n]` переводит n-1 в n; промежуточные данные unknown, финальные проверяются validate. Синхронная цепочка, один commit после успеха, никакого автоматического downgrade. Миграции выполняются при создании/открытии стора. Чтение не должно неожиданно коммитить миграции; внешняя несовместимая смена версии после открытия должна сообщаться явно.

defaults — фабрика, отсутствие записи не создаёт запись. getServerSnapshot возвращает стабильные defaults; приложение отвечает за одинаковые defaults на сервере и клиенте. getSnapshot стабилен, пока исходная запись не изменилась. reset удаляет запись.

React: useValue<T>(store: Store<T>): T; useStore<T, S>(store: Store<T>, selector: (value: T) => S, isEqual?: (a: S, b: S) => boolean): S. Реализация через useSyncExternalStore, не через эффект с зеркальной копией состояния.

## Следствия и ограничения

Обновление одного стора — одна запись KV, а не транзакция между несколькими ключами. Подписки ограничены экземпляром KV. Миграции и update должны быть чистыми; проверить защиту исходной записи от случайной мутации при провале. Значения, переданные или полученные пользователем, считаются immutable.

Стабилизация localStorage snapshots делается по исходной строке, с повторной проверкой чтения при каждом get. React не входит в граф импортов `hoke/kv`.

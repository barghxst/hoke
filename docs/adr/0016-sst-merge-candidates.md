# ADR 0016: потоковое объединение SST-кандидатов

Статус: принято для C5b. Расширяет файловые примитивы ADR0015 без изменения формата SST v1 или публикации состояния browser DB.

## Контракт

`hoke_core::sstable::merge_tables(destination, sources)` объединяет до64 immutable SST в пустой отдельный destination. Sources передаются от самого старого к самому новому; одинаковый ключ берётся из последнего источника. Порядок задаёт будущий coordinator: случайные имена файлов не определяют хронологию. Пустой список создаёт корректный пустой SST.

Победивший tombstone сохраняется всегда. Без знания полного набора более старых данных удалять его нельзя: частичная compaction иначе воскресит удалённый ключ. Native Database продолжает применять свой прежний протокол полной compaction; этот срез его не меняет.

## Реализация

Курсор каждого источника указывает на уже загруженный key index. При fan-in64 минимум выбирается из фиксированного массива курсоров без дополнительной копии всех ключей/значений. Для одинакового ключа читается только самая новая запись, затем продвигаются все соответствующие курсоры. TableWriter записывает результат в существующем SST v1 формате.

Память включает индексы открытых источников, индекс output writer и временные буферы одной выбранной записи; полный набор values не материализуется. Это не константный общий RSS: размер индексов зависит от данных, а декодирование может временно копировать payload. Число записей и размер выходного индекса ограничены существующими SST caps, проверяемыми по мере записи. Ошибка может оставить неполный кандидат.

Альтернатива с BTreeMap всех values проста, но вернула бы полную материализацию данных. Heap может быть полезен при большом fan-in; фиксированный предел64 позволяет начать с простого bounded cursor merge. Алгоритм не объявляется оптимальным без измерений.

## WASM и OPFS

WasmSst.merge получает отдельный destination adapter и массив source adapters в указанном порядке. Проверяет count до обращений к storage, открывает все source indexes до обращения к destination, объединяет, выполняет file flush и открывает output reader. JS handles остаются у вызывающего кода.

Внутренний `mergeSstCandidates(directory, names)` копирует/проверяет список имён, отклоняет duplicates и более64 sources до I/O. Открывает источники с create:false и исключительными sync handles; missing/locked source не создаёт destination. Затем выбирает свободное имя и создаёт отдельный output. Уже открытые SstFile на этих source names вызывающий код должен предварительно закрыть.

После merge все input handles закрываются до возврата SstFile результата. Ошибка инициирует cleanup всех ресурсов, сохраняя первую причину и имя возможного orphan, в том числе когда create мог выполниться перед исключением. Ошибка close не скрывается; если платформа не освободила handle, может потребоваться завершение Worker. Directory ownership остаётся обязанностью будущего coordinator.

32MiB — предел transfer packet при create/scan, не предел итогового SST после streaming merge. Итог может содержать более1000 записей и превышать32MiB; чтение по-прежнему использует ограниченные scan или lookup.

## Целостность и границы

Открытие source проверяет header/index/record headers. CRC payload читаемой победившей записи проверяется во время merge; её повреждение может обнаружиться уже после записи начала output. Перекрытые старые payload не читаются. Merge не является полным scrub всех входов и не ремонтирует повреждения.

Исходники никогда не переписываются и не удаляются. Даже полный успешно синхронизированный output остаётся кандидатом: active root не переключается, пользовательский commit ACK не отправляется, WAL не очищается. Batch, reclamation и включение SST в openDB требуют выбора публикации по ADR0014. Worker protocol2, WAL v1 и долговременные bytes не меняются.
